# CuBit runtime TrueType

The shared Ada toolkit and desktop compositor now rasterize bundled IBM Plex
Sans Regular / Sans SemiBold / Mono Regular through `ab_glyph_rasterizer` and
`ttf-parser`, in Rust
userspace. Native builds are `no_std + alloc`, static, and use CuBit's SPARK-core
allocator adapter. The Linux preview uses the same glyph code with the host
allocator. There is no C font engine, font syscall, or separate font service.

## Boundary and rendering

`CuBit.Fonts` is the small Ada interface. Only the three bundled faces (face
numbers 0 Sans, 1 Mono, 2 Sans SemiBold, in `CuBit.Fonts.Face` order; SemiBold
is Desktop's emphasis face, with the same hinting, stem darkening, kerning and
phases as Regular) and two raster sizes are accepted; there is no caller-supplied font parser input or arbitrary
output pointer. The C calling convention is an ABI, not a C implementation.
The renderer returns a stable read-only glyph pointer after release/acquire
publication. A bounded table of 2,280 pointers (three faces x two sizes x four
subpixel phases x 95 ASCII characters) indexes the cells; a cell (1,184 bytes)
is allocated the first time it is drawn and is never moved or evicted, so a
process pays only for the glyphs and phases it uses (the table itself is
36 KiB of BSS).

Text quality (backlog UI-026), all in this crate except the blend:

- **Light hinting**: vertical only. The baseline, x-height, cap height and
  ascender (blue zones measured from x/o/H/O/l) snap to whole pixels, and
  overshoots under half a pixel are flattened, as FreeType's auto-hinter does
  at small sizes. Points move only vertically, piecewise-linearly between
  zones; no horizontal distortion.
- **Subpixel phases**: every cell is rasterized with its pen origin a
  quarter pixel step (0, 1/4, 2/4, 3/4) right of column `ORIGIN` (2). All ink
  is kept, left of the origin and past the advance; the cell records its
  ink box so blits touch only inked pixels.
- **Layout table** (`cubit_font_layout`): per face, unhinted advances and
  GPOS pair kerning (the default language of `latn`/`DFLT`'s `kern`
  feature, pair-adjustment formats 1 and 2) for every printable-ASCII pair,
  in 1/64 pixel at the 13 px em. Built once on first use (about 0.3 ms per
  face here), held in static storage (an 18 KiB table is above the native
  small-object ceiling). Toolkit and Desktop measure and place text only
  through it (`CuBit.Fonts.Width` and `Lay_Out`). The monospace face keeps
  its 8-pixel grid, unkerned.
- **Density masks** (`cubit_font_raster_mask`, for non-unit densities and the
  desktop compositor's glyph caches) share the same rasterizer: hinted, pen
  origin `ORIGIN` logical pixels in, ink clipped only to the raster.

Coverage is still linear 8-bit; the gamma/contrast correction is applied by
every blend path through one table (`userspace/lib/compositor/glyph_gamma.ads`,
generated by `glyph_gamma_tables.py`, also spliced into the Vulkan glyph
shader). Legacy 8x16 console drawing remains separate.

Warm lookup is allocation-free and lock-free (an atomic readiness load).
Cold raster work allocates temporarily and is not hard-real-time. Outlines
stream directly from the parser into coverage scratch, without collecting a
heap vector of curves. Unhinted rasters at all four phases are regression-
compared against `ab_glyph` at the same subpixel position (at most one
grayscale level of rounding difference); hinted rasters are checked for
grid-aligned x-height/baseline rows and unchanged horizontal extent. The
layout table is checked against HarfBuzz for all 27,075 ASCII pairs of the
three faces by `tests/ui-fonts/check_kerning.py` (Linux-hosted oracle).
The native allocator now acquires small-object backing in 1 MiB chunks so a
416-byte font allocation does not demand a fresh 16 MiB arena.

## Build and test

Use Nix; it supplies the exact font files and Cargo vendor tree. Builds remain
`--locked --offline` after Nix supplies dependencies. Normal desktop build
targets and the Linux preview build the correct static archive automatically.

```
nix develop -c make -C kernel run-desktop
nix develop -c make -C kernel ccl-ui-preview
nix develop -c make -C kernel test-ui-fonts test-procmgr-reads
nix develop -c make -C userspace/rust fonts-bench
```

Hosted tests cover all glyphs/sizes, concurrent publication, metrics, ABI layout,
grayscale output, clipping, pitch padding and transparent drawing. The Linux
dialog/editor/theme regressions and native QEMU runs cover toolkit consumers.
These tests do **not** formally verify the rasterizer, parser, unsafe ABI or
allocator pointer/synchronization boundary. The existing metadata proof is
separate and unchanged. See [third-party notices](THIRD_PARTY.md).

One hosted optimized run on this workstation (2026-10-18) measured 760 cold
normal-size cells (2 faces x 4 phases) in 3.4 ms, both layout tables in
0.65 ms, and two million warm lookups in 7.7 ms (~3.9 ns/lookup). The largest
allocation is a published cell (1,184 bytes; 1,780 at double size); scratch
is released after each glyph. Both sizes have a regression ceiling of 4,096
bytes per allocation to avoid triggering the native large-object arena. This
is a cache microbenchmark, not native repaint time or an input-latency
guarantee.

## Native bring-up fixes

The desktop ELF grew beyond a single 16 MiB grant. Procman now reads exact
1 MiB windows directly into the final buffer, refusing partial/error replies
and quarantining it if retirement cannot be confirmed. The development disk
also exhausted its old 64 MiB capacity: `debugfs` left truncated payloads while
returning success. Its new builder sizes from the payload, verifies every file
by SHA-256 readback, and atomically publishes only the complete image.

## Deliberate limits / next work

- Printable ASCII; other Character values map to `?`. No UTF-8 shaping,
  ligatures, bidi, font chooser or untrusted font files yet. Kerning covers
  printable-ASCII pairs only.
- The 26-pixel raster is tested groundwork, not connected to per-output DPI.
  SDL's existing integer canvas scaling still scales the whole surface. This
  does not yet solve fractional/mixed-DPI monitor rendering.
- Grayscale outlines with light blue-zone hinting, not a TrueType bytecode
  interpreter, stem snapping or subpixel LCD rasterizer. Retain grayscale
  for rotated displays and compositing. The density masks (desktop
  compositor, non-unit densities) have no subpixel phases yet: glyphs land
  on the nearest pixel of the fractional pen.
- Static font copies/cache per process; no cross-process cache or shared font
  service. Large-object allocator backing remains coarse-grained.
- Fatal native Rust panics are logged without allocation, then terminate that
  process. Recoverable OOM inside dependency rasterization remains future work.
