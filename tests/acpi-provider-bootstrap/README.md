# Bounded snapshot provider orchestration

The driver preflights a complete catalog against server capacities, starts once, imports immutable tables in order and finishes once. It never retries a mutation after an unknown outcome; completion pages0/13–16 are diagnostic observations only. A Complete observation cannot attribute a lost Finish to this caller. Raw pages are not converted into new authority or success claims.

The injectable callbacks are trusted and synchronous: a known reply belongs to that exact authenticated call. One owner serializes mutations and grant retirement. Index-to-bytes mapping must remain immutable until provider-side retirement/reclaim is confirmed. Cleanup is independent of admission and is not a wire acknowledgment: Native_Blocks hides receiver Pending state. Tests model provider lifecycle and use real endpoint/Dispatch_Block, not kernel mapping operations. Native asynchronous correlation, catalog export, launcher and broker binding remain unimplemented. No PID or physical address creates authority.

This driver does not configure Notify interest. The trusted broker must configure interest before Finish/device initialization if startup _INI notifications are required; successful catalog upload does not imply that interest was enabled. Logger behavior is unchanged.
