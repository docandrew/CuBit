# ACPI HID initialization ancestry

Export TMPDIR=/home/doc/cubit-build-tmp before Nix, then run bash tests/acpi-hid-ancestry/run.sh. --validate-only checks the closed catalog and tools without compiling. The suite contains all helpers and fixtures in this repository; it does not require private workspace files.

Actual hosted Core, controlled actual device initialization Session, filtered native detector and fresh collector are exercised at AML32/64:24 normal/history/current/deeper Device/Processor/Thermal fixtures and16 explicit fault/budget/history/reset scenarios per width (80executions). Checks cover intentionally skipped inactive INI versus reactivated uninitialized devices, current ancestors, missing status defaults, foreign/unstarted histories, same total fuel, interrupted callbacks and retained Core roots. Reset is an attempted reset REFUSAL by the existing one-shot snapshot API, not a reset native owner.

Five wrappers include captured Lenovo methods plus explicitly modeled hardware helpers; the other fixtures are controlled policy examples, not laptop observations. Five controlled status-transition fixtures and eight Processor/Thermal initialization fixtures are compared with34ACPICA executions. The latter use automatic ACPICA initialization to check parent/leaf INI counters, not thermal management or CPU control. Fatal/indeterminate/overcharge callbacks are modeled provider results; retained CID roots use actual Core evaluation. Heap, native evaluator/logging boundaries and physical providers are modeled. Whole Core compiles O0/gnatp; no assertion-enabled whole-Core, new SPARK, native or hardware validation is claimed.

Each compile180s/test30s/ACPICA5s is bounded, nice19/j1, stack64MiB/core0, AS24GiB (ACPICA128MiB/2MiB stack), output1MiB. Sources/tools/copies are rehashed around every command. The separate native-entry suite checks the actual SDK, component/Startup and concrete owner bindings. Passing this suite does not complete the full userspace ACPI/verified AML goal.

A controlled two-read status transition also verifies that a leaf becoming absent after the path gate cancels retained CRS before template copy or DSM, while retaining complete status diagnostics and cleanup accounting.

Object-kind boundary checks reject empty and ordinary data descriptors before status AML or default presence; Processor/Thermal objects with a compatible CID remain invalid HID leaves. Four additional real-AML fixtures exercise temporary names inside repeated status methods and CopyObject changes from integer to buffer/string during INI or STA. These test ordinary value mutation and temporary namespace cleanup, not persistent binding replacement, dynamic SSDT loading or unload.

A modeled owner callback also prematurely releases a real retained CID result before returning it. The actual Core release then rejects the stale result; current-status cleanup failure must trigger recovery even with zero remaining roots, and the native one-shot fence prevents retry. The provider contract is deliberately violated in this case; it does not represent ordinary AML behavior or a hardware test.

Two additional AML32/64 fixtures invoke the actual ancestry policy for every Device, matching native discovery. An unrelated device with no local _CID has either a real Fatal _STA or an unadmitted Field read. Both must be skipped using metadata, while discovery still reaches the initialized Lenovo-shaped HID leaf. Possible candidates retain current ancestor/leaf status checks. These are four additional hosted executions; no new hardware authority is modeled.

The zero-address-resource case presents a compatible seven-bit general-call address before the valid Lenovo-derived touchpad. Both AML widths exercise actual Core/owner/native discovery: the unsupported candidate is counted once, its copied diagnostic is retained, and discovery continues to the later valid device. This tests hosted detection, not native execution or touchpad input.
